# Universe One Teacher — school pilot launch gate

Status: **prototype only; not approved for classroom deployment**. Automated checks are not a substitute for educator review, security assessment, or actual device testing.

## Minimum viable pilot scope
- [x] Browser-based Learning Quest: five rooms and twenty practice questions
- [x] Locally saved challenge completion and student-controlled CSV summary without student identifiers
- [x] Automated gameplay, security, classroom, and release checks (verify each candidate commit)
- [ ] Independent educator review of every question, explanation, accessibility flow, and linked source
- [ ] Define grade bands, learning objectives, standards mapping and content version for each lesson
- [ ] Test on actual target phones, tablets, school browsers, and assistive technology
- [ ] Publish accessible privacy notice, support contact, retention/deletion procedures and incident response plan
- [ ] Assess child-directed use and applicable student privacy obligations with qualified counsel before collecting student data
- [ ] School IT review: content filtering, accessibility, network requirements, security and procurement
- [ ] Written school pilot agreement, owner approval, teacher onboarding, consent/permissions where applicable
- [ ] Pilot feedback, measurable learning outcomes, issue triage, and rollback plan

## Pilot boundaries
Start with a small **teacher-supervised, browser-only demonstration** using no student accounts or identifiable learner data. Do not claim accreditation, official curriculum alignment, FERPA/COPPA compliance, production LMS interoperability, VR support, or classroom approval without evidence. Do not import rosters or student records during the prototype stage.

## Future integration track
Evaluate LTI 1.3/Advantage and OneRoster requirements with actual partner schools; specify identity, authorization, grades, rostering, tenant isolation, data agreements and audit trails before implementation. Add languages incrementally with human-reviewed translations and right-to-left/accessibility testing, not claims of universal language coverage.

## Release decision
A named project owner and a participating school must sign off on the pilot scope and completed checklist. Keep production deployment blocked until applicable release and privacy gates are satisfied.
