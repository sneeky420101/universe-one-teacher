# International education release gates

**Status: pre-launch staging. This checklist is not an assertion of completion.**

| Area | Required evidence before a production claim |
|---|---|
| International standards | Current primary-source standards, jurisdiction, grade, subject, version, permission, and qualified educator review |
| Content quality | Factual source citations, age-appropriate pedagogy, error reporting, correction history, assessments validated by educators |
| Language access | Professional translation review, right-to-left layout testing, regional terminology, accessible language switching |
| Adaptive tutoring | Verified mastery model, safe feedback, bias/fairness testing, safeguards against fabricated answers |
| Child privacy | Jurisdiction-specific legal assessment (including COPPA, FERPA when applicable, GDPR/UK GDPR and regional laws), consent flows if necessary, data minimization |
| Accessibility | WCAG 2.2 AA testing with keyboard, screen reader, contrast, reduced motion and captions where needed |
| Meta Quest | Supported headset/browser compatibility, permission prompts, controller and hand-input testing, VR comfort and non-VR fallback |
| Infrastructure | Automated test results, real HTTP/browser checks, monitoring, backups if data is later stored, incident handling, security review |
| Legal/IP | Licensed learning materials, copyright provenance, terms and privacy notice reviewed before public onboarding |
| Launch | Owner's explicit authorization to lift the pre-launch hold; no unapproved public marketing or checkout |

## Current scope
The app is a limited source-linked classroom preview, global education authority directory, WebXR prototype and local adaptive-practice sample. It does not currently contain all world curricula or a validated generative AI tutor.

## Engineering next sequence
1. Create a versioned official-standards import format with source/license/reviewer gates.
2. Build accessible locale bundles with human-reviewed translations.
3. Extend pathways to use approved catalog objectives and assessments rather than hard-coded demos.
4. Add automated accessibility and browser checks plus actual Meta Quest device acceptance tests.
5. Implement a privacy-preserving tutor only after provider, safeguarding and evaluation decisions are approved.
6. Conduct jurisdiction-specific legal review, independent security review and controlled acceptance testing before production.
